- `ingestion/osm.py`: live administrative relation discovery, polygon rings and
  holes, explicit Overpass endpoint, separate bounded category queries, safe
  retries, exact final count sentinels, query identity sets, raw snapshot rights
  and integrity checks. HTTP 403/429 and incomplete output remain failures.
- `ingestion/categories.py`: seven activity groups and finite OSM tag selectors.
- `ingestion/normalize.py`: NFC names, explicit language fields, untyped aliases,
  stable type/ID identities, representative coordinates, boundary filtering,
  direct source facts and deterministic derived summaries, Pydantic validation.
- `ingestion/cli.py`: root CLI, export before database, mandatory sidecar, source
  registry/report, sample records, immutable generations, kernel import lock,
  S01 upsert integration and safe persistence counters. No direct database SQL.
- `ingestion/validate.py`: checksum, schemas, identity/coordinates/sidecar controls
  and compact quality report. Detailed venue review remains D05/D06.
- `data/.gitignore`: raw, normalized, reports and transfer artifacts excluded.
  `ingestion/README.md` documents reproduction and consumer requirements.

Flow: permitted live OSM/saved raw snapshot -> discovered administrative boundary
-> node/way/relation queries per category -> exact response checks -> representative
point clipping -> canonical records plus metadata -> JSONL + checksum manifest ->
S01 upsert_pois -> import and quality reports. Partial fetches do not delete or
deactivate existing POIs. Exact repeated identities update; same-brand branches
and other distinct OSM IDs are not merged by names.

## Contract handoff and limitations

1. **Mandatory manifest for S03.** Contract 1.1.0 forbids extra POI fields and
   cannot represent multilingual names, aliases, center approximation or per-fact
   verification. These live at `manifest.normalization.records[poi.id]`. S03 must
   verify JSONL SHA-256 and join that sidecar. A DB record alone does not convey
   coordinate accuracy. Request to Sabyrzhan: consume sidecar now; review a future
   versioned contract extension if these fields must live in database documents.
   Source edit/version is also sidecar-only. With null factual observed_at, S01
   cannot use those edit/version values to reject an older historical snapshot.
   Replaying the same snapshot is safe for identity; chronological source-version
   protection needs the owner's contract/repository decision.
2. **Local import ID.** D02's import_id labels its report/artifacts. S01 returns
   counters only, not the database import_runs row ID. database_import_run_id is
   explicitly null. Request an interface extension if a DB audit identifier is
   required; D02 does not edit repository.py or query the audit table itself.
3. **Coverage remains unknown.** Successful category queries establish an OSM
   extraction within the boundary, not city completeness. Report raw counts,
   missing names/coordinates, boundary exclusions, category/type counts and grid
   occupancy. No known denominator or field verification is fabricated.
4. **Approximate centers and duplicates.** Way/relation centers may not fall on
   the feature; invalid/outside points are excluded. Cross-ID representations may
   remain duplicate venues; quality checks flag potential exact-name/coordinate
   groups without merging network branches. Detailed 10–30 POI review is deferred.
5. **Publication recovery.** One OS lock prevents interleaving imports. A crash
   between individual top-level file replacements can leave a hash mismatch;
   reject it and use the immutable normalized/runs/<import_id> pair.
6. **Delivery evidence.** The user selected an archive and handoff text in this
   chat. No direct message or acknowledgement from Sabyrzhan is claimed. Raw and
   normalized files are ignored by Git and must travel as the attached artifact.
7. **Shared test discovery.** Current pyproject.toml lists only backend/tests.
   D02 runs backend/tests and ingestion/tests explicitly. Request to Sabyrzhan:
   include ingestion/tests in shared pytest/CI discovery when integrating this
   change. The root configuration is not edited by D02. No remote CI run is claimed.

OSM edit/retrieval/verification timestamps; null vs inferred facts; atomic files
vs atomic multi-file publication; OS locks; S01 transactional upserts; ODbL;

1. Why not merge same-brand venues? A brand identifies a chain, while type/ID
   identifies a source object; branches remain distinct without stronger evidence.

   no successful query established that no POIs exist.
