  values, unknown hours/price/availability, safe source actions. Free explanation
  appears only when generated_locale matches UI locale; otherwise local code
  templates replace it. Search-time route facts are labelled as a snapshot.
- `components/DiscoveredEventCard.tsx`, `EventSearchSources.tsx`: D03 listings,
  eligible sessions, per-field verification, price-from/conditions, unknown
  tickets and inspectable citations. Generated citation paragraphs/titles do not
  become untranslated UI prose. A listing does not become a verified session.

  three known destination points. Coordinate view works without a key; optional
  MapGL fits all points and retains native provider labels. Origin is hollow,
  alternatives are numbered. Unknown coordinates are not guessed. Event sessions
  with different/unknown venues do not silently choose the first destination.
  Card selection requests one route; response-local memory cache and separate
  active/abort guards prevent late route updates. Locale does not rebuild it.
  Retry works after a failed request. Outbound/return, 2GIS attribution/freshness,
  destination approximation and warnings are displayed; no route line is invented.
- `locales/{kk,ru,en}/common.json`, `src/index.css`, `frontend/README.md`:
  matching local dictionaries, accessible labels and compact single-page states.
  Intl uses KZT and Asia/Almaty. Proper names retain source text. No account,
  calendar grid, favorites, itinerary editor or purchase flow was added.

Ticket actions use a safe sourced booking_url only with booking_url provenance;
otherwise they open the confirmed source URL. They promise a source check, not
inventory, booking or purchase. No source payload, query or location history is
persisted. Only the existing UI language preference goes to localStorage.

## Study topics and interview checks

Study: request lifetimes and correlation; local codes versus generated prose;
ephemeral provenance and source rights; known/unknown/unavailable/no_match;
Intl timezones; independent route legs and approximate destinations.

1. **Why does language switching make no provider call?** Stored facts/codes
   re-render locally; locale is excluded from search/route/map request lifetimes.
   Only the next explicit search or retry uses the new locale.
2. **Why are AbortController and generation checks both useful?** Abort releases
   cancellable work; generation/active guards also reject late completions from
   transports or mocks that ignore cancellation.
3. **Why is a listing not a confirmed session or purchase action?** A title and
   URL do not prove a date, venue, admission or inventory. The source action asks
   the person to check those facts; unknown values remain visible.
