## Changes and flow

- `backend/app/indexing.py`: one Unicode NFC text version, `poi-source-v1`;
  available names, aliases, canonical categories and attributed source facts.
  Source IDs and assertion kinds are embedded in the text. Unattributed
  descriptions and unknown/generated claims do not enter it. Complete sidecar,
  source timestamps, derived markers and coordinate precision remain metadata.
  Indexing requires every source's storage and indexing permission.
- `scripts/embed_pois.py`: root module CLI, paired-export checks, exact database
  snapshot comparison, dry run, lexical-only mode, bounded indexing, safe JSON
  reports, stable keyset reads. Documents are written in batches up to 100;
  embeddings use batches up to 32. Texts over 8,000 UTF-8 bytes are rejected,
  never truncated; the actual corpus maximum was 2,520 bytes.
- `backend/app/openai_client.py`: shared `responses.parse(text_format=...)`
  with Pydantic and `store=False`; validated batch embeddings, response model,
  dimensions, index ordering, finite/nonzero vectors and safe provider errors.
  The existing 20-second request timeout and zero SDK retries remain.
- `backend/app/intent.py`: interests, named places, text language, categories,
  time/budget intervals, indoor/outdoor, return requirement and explicit datetime.
  Extraction does not receive UI locale or form defaults. Explicit form fields
  are identified by the existing `explicit_fields` contract. Compatible upper
  bounds use their minimum; impossible intervals and explicit boolean/datetime
  contradictions return `clarification`. `indoor_only=false` means no indoor
  restriction, not an outdoor requirement. Text may override non-explicit defaults.
- A numeric-unit presence audit for kk/ru/en detects omitted time/KZT fields.
  It permits one re-extraction, then requires clarification if omission persists.
  This is a presence check, not a complete semantic parser or currency converter.
- `backend/app/repository.py`: PostGIS radius prefilter, NFC/Unicode names and
  aliases, pg_trgm similarity/word similarity, canonical category matching and
  exact pgvector cosine search. No locale filter or per-language index.
  Parameterized SQL, discovered extension schemas, bounded limits and existing
  pool/TLS/timeouts are retained. Writes recheck source snapshots under row
  locks; no provider request happens while holding those locks. Unknown batch
  write outcomes are reported without fabricated success/rejection counts.
- `backend/app/retrieval.py`: up to 12 candidates by default, maximum 30, with
  canonical IDs/records, sources, missing source/input fields and selection
  diagnostics. Includes straight-line distance and coordinate precision, never
  an ETA. `unavailable` database and `no_match` remain distinct. Provider failures
  remain visible when lexical fallback is used; unresolved intent is flagged.
- `scripts/retrieval_smoke.py`: reproducible real kk/ru/en, mixed-name, conflict
  and explicit lexical-only probes; exact time/budget/indoor/return assertions.
- Tests cover precedence/conflicts, source rights, hashes, malformed transfer,
  safe provider failures/refusals, stale writes, model/version separation,
  multilingual SQL, geo filtering and control mutations. CI's existing isolated
  PostgreSQL job now also runs `test_retrieval_integration.py`.

Flow: validated D02 pair + current database records -> permitted source text ->
SHA-256 and version/model/dimension comparison -> changed document embeddings ->
snapshot-checked writes. Request -> structured extraction -> deterministic
constraint merge/audit -> query embedding or explicit lexical fallback ->
PostGIS/pg_trgm/category/vector SQL -> grounded candidates for S04.

## Study topics and interview preparation

Study NFC normalization, trigrams vs cosine similarity, structured output vs
semantic validation, explicit/default constraint precedence, source rights,
optimistic snapshot checks, database locks and idempotent batch processing.

1. Why require the same embedding model and dimension? Equal vector length does
   not make different model spaces comparable; SQL also checks version/hash.
2. Why does replay avoid API charges? A hash of stable attributed text plus
   model/dimensions/version identifies reusable embeddings; metadata may refresh.
3. Why distinguish unavailable and no_match? Infrastructure failure supplies no
   evidence that suitable records do not exist; lexical fallback also exposes
   unavailable intent rather than silently assuming constraints.

Official API references checked against installed openai SDK 2.54.0:
[Pydantic Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses)
and [embedding dimensions](https://developers.openai.com/api/reference/resources/embeddings/methods/create).

   indexer. CLI embedding writes now require the staged text hash/version to
   match and update only the embedding; a superseded batch reports `stale` and
   does not rewrite the current search document or metadata.
