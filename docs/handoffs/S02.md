- `backend/app/services/twogis.py`: single standard-library REST adapter,

- `backend/app/main.py`: existing POST `/api/route` and alias now use the adapter;
  dynamic 200/503, localized warnings, Cache-Control=no-store. Health remains
  keyless and never initializes a provider.
- `backend/app/schemas.py`, `contracts/api-v1.md`, generated route schema and
  codes: approved v1.2 route-only extension. Request/search/record shapes unchanged.
- `backend/app/settings.py`, `backend/.env.example`: off-by-default capability

- `backend/tests/test_twogis.py`: synthetic responses and observable API tests.

  synthetic asymmetric round trip, validated by JSON Schema and Pydantic.
- `scripts/twogis_smoke.py`, root README and this handoff: reproducible status-only
  external probes, configuration and consumer guidance.

Route flow:
`RouteRequest validation -> capability/key/rights gate -> lon/lat walking POST
-> HTTP + provider status/type/result validation -> meter/second leg + provenance
-> optional independent reversed POST -> aggregate only complete successful legs
-> v1.2 RouteResponse with localized warnings`.

App coordinates are named latitude/longitude; provider points explicitly use lon,
lat and type=walking. The transport is always walking, output=summary,
alternative=0 and save_route=false. No request body, URL with key, provider error
body or raw GPS/query is logged. Provenance has a fixed keyless endpoint, retrieval
time and locale; no coordinates. No persistence or response payload cache.

Transport uses urllib outside the event loop via asyncio.to_thread: 5-second
socket-operation timeout, 8-second await deadline per call, 256 KiB body limit,
incremental body reads/deadline checks, response context cleanup and no redirects
or retries. Cancellation propagates. Python cannot forcibly cancel an already
running urllib worker; it exits on its socket/read deadline. DNS/connection/header
work still has stdlib/OS timeout limitations. This is an explicit limitation, not
a guarantee of instantaneous socket cancellation. Independent return calls can
take up to two await deadlines. No automatic retry storm after 429.

Places flow:
`separate Places + discovery rights/key gates -> verified live Astana region
-> bounded GET /3.0/items -> projection to id/name/point/rubric IDs + provenance`.
Only items.point,items.region_id,items.rubrics are requested as extra fields;
page_size=3. Provider-default fields may still arrive but unneeded fields are
discarded. Missing point stays null; any point is approximate, never a verified
accessible entrance. Source observation time stays null rather than being
fabricated from retrieval time. No DB/OpenAI calls, dumping or real fixtures.

## Route contract for D04

See [API v1.2](../../contracts/api-v1.md#walking-route-s02-v12) and
[route-response schema](../../contracts/route-response.schema.json).

| Situation | HTTP / state / UI action |
| --- | --- |
| All requested legs succeeded | 200 known; show total estimate and approximate destination warning |
| Return not requested | return_route.status=not_requested; no return metrics |
| Return failed after outbound success | Preserve outbound metrics; total=null; never double outbound |
| Route graph reports no route | 200 unknown; leg reason=route_not_found; do not show ETA/no_match |
| Origin missing with approved provider | 200 unknown, reason=missing_origin; request origin |
| Disabled, missing key, unknown rights, invalid settings | 503 unavailable; reason=disabled/key_missing/rights_unconfirmed/invalid_settings |
| Timeout, network error, 401/403, 429, other HTTP error | 503 unavailable; reason=timeout/network_error/access_denied/rate_limited/http_error |
| HTTP 200 FAIL/POINT_EXCLUDED/ATTRACT_FAIL | 503 unavailable; reason=provider_fail |
| HTTP 200 OK with empty/malformed result or invalid metrics | 503 unavailable; reason=invalid_response |

Legs contain distance_meters, duration_seconds, provenance and a nullable reason.
Unknown/unavailable/not_requested legs have null metrics/provenance. Complete
trip minutes are ceil(sum of normalized leg seconds / 60), not doubled outbound
or a sum of independently rounded minutes. Provider decimals are rounded upward
to whole meters/seconds; negative/nonfinite/bool/string/missing/oversized metrics
are rejected. Zero is valid. No straight-line ETA fallback.

Routing locale: ru -> ru, en -> en, kk -> ru. Places: ru -> ru_KZ,
en -> en_RU, kk -> kk_KZ, using the documented list. UI language remains the
requested kk/ru/en; provider names are not silently translated source facts.
Summary output contains no WKT/GeoJSON/line. Detailed geometry is explicitly
deferred by user agreement; D04 must not draw a straight line as a known route.
Every destination is labeled approximate; accessibility/entrance is unverified.

For enabled live output, D04 must implement the reviewed attribution scenario
(the current public terms specify a 2ГИС link to http://dev.2gis.ru), avoid
localStorage/service-worker caching of provider-derived responses, and keep
catalog data outside AI/ranking. Frontend implementation/acceptance is not part
