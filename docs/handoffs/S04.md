## Shared Responses client and unchanged D03

AIClient/OpenAIClient now provide the requested method:

```python
async def search_web(self, text: str, *, instructions: str = "",
                     allowed_domains: tuple[str, ...]) -> Mapping[str, object]: ...
```

It uses the configured SDK/model, store=False, zero retries, web_search with
explicit domain filters, tool_choice=required and the full
web_search_call.action.sources include. The completed envelope preserves tool
status, sources and annotations rather than reducing it to output_text.
Search is bounded to two hosted tool actions, 4096 output tokens and a 40-second
per-call timeout. An explicit stop instruction shares that budget across search,
page opening, finding and languages. Top-level completed alone is insufficient:
an unfinished tool action, refusal, empty answer or invalid output fails safely.
Serializer warnings are suppressed before explicit validation because the SDK
may otherwise print raw malformed provider values.

Generic SDK timeout remains 20 seconds. parse_response keeps its default 2000
output tokens and accepts a validated optional integer budget in 1..8192.
The D03 adapter uses structured Pydantic extraction with 4096 tokens, hard-bounded
to three events and three sessions each. It borrows the same client and never
closes it or creates another SDK. The HTTP layer owns and closes the client.
D03's outer deadline is 80 seconds. Cancellation propagates.

A real provider 400 exposed format=uri in D03's HttpUrl transport schema.
EventExtractionBatch removes only that unsupported annotation from the schema
sent to Responses. Pydantic still rejects invalid URLs, and D03 still checks
allowed, actually consulted source/citation membership. No source DTO or global
SDK behavior was patched. A standalone live structured parse subsequently passed.

Official documentation checked:
[web search](https://developers.openai.com/api/docs/guides/tools-web-search),
[structured schemas](https://developers.openai.com/api/docs/guides/structured-outputs).

TransientEventSearchResponse contains request_id, contract_version, status,

warnings, excluded_sessions and rejected_events. Cards are at most three;
listings retain discovered/incomplete/withheld sessions separately. Counts are

citation contexts and provider tool payloads are absent from HTTP.

All transient sources expose storage_allowed=false and indexing_allowed=false.

anchor, not a guaranteed page-fetch/modification time. Parent-event, session,
consulted-source, venue and field-check references are validated. Permitted OSM
venue references retain their identities but do not grant event-content rights.
HTTP uses Cache-Control: no-store. No real transient event response was saved in
the repository, cache or index; live checks reported operational metadata only.

| State | D04 interpretation |
| --- | --- |
| partial + items | Conditional session alternatives; fit_status remains unknown |
| partial + listings only | Discovered listings/withheld sessions, not recommendations |
| unknown | Clarification or insufficient grounded facts, never invented absence |
| unavailable / HTTP 503 | Required-provider failure; inspect the typed envelope |
| live_web_search=passed | Completed tool/source/citation evidence, not independent source truth |

The event contract rejects no_match: a bounded search cannot prove city-wide
absence. Current D03 has unknown ticket inventory, so event cards cannot become

coordinates and poi_id remain unknown unless independently established.

schemas and TypeScript enum/field checks still pass; this is not a claim that the

## Constraint and explanation decisions

POI time is ceil((outbound + requested independent return seconds)/60), plus
5 minutes entry, a recommended visit and 5 minutes buffer. Visit recommendations
are 30 minutes for walk/food/shopping/other and 45 for
museum/culture/sport/entertainment. The nested source POI is unchanged; the card
estimate is advice, not an observed source fact. Unknown route or hours never
confirms fit; a known hard conflict is filtered before expensive route requests.

Opening hours cover arrival through entry and visit end. The deliberately narrow
weekly subset supports 24/7, simple day/range lists, intervals, breaks, closed
days and midnight crossing. PH/SH, overlapping overrides, holidays, exceptions,
comments and unsupported text stay unknown. There is no full calendar parser or
implicit waiting until opening.

Exact price is KZT per person and needs field provenance. Unknown/price_from
cannot prove a hard budget; an above-budget lower bound can reject. Indoor and
location also require facts. Quietness/outlets/accessibility lack modeled facts;
explicit requirements request clarification. A presence check is conservative,
not a complete language parser. Lost upstream price qualifiers cannot be recovered.

For events, arrival plus entry must precede start; known end, independent return
and buffer must fit the original window. An unknown end cannot hide a start
already outside that window. A known return can prove failure even when outbound
is unknown. Production time is refreshed after discovery, routes and explanation,
and newly past/unreachable sessions are withheld without repeating provider calls.
Tests can inject a fixed clock. Approximate centers do not verify an accessible
entrance. Venue matching uses at most three exact name/address lookups against
permitted POIs; a truncated 30-row set cannot prove uniqueness and stays unknown.

One structured explanation call covers up to three cards, with a six-second outer
deadline and no retry. IDs, source IDs, locale, activity, codes and exact safe
activity phrases are checked. Arbitrary critical prose cannot pass. Backend
rendering adds advice and missing checks; refusal/incomplete/timeout/invalid facts
use templates. Names, descriptions, raw query/GPS, source instructions, lower-bound
prices and all route/2GIS-derived data stay outside the explanation prompt.
Runtime typed assertions remain labelled discovered_unverified. There are no fake
persistent records or invented storage rights. D03 has no activity classifier;
other is used instead of guessing. Existing codes plus missing fields support
D04 localization; fallback_explanation(card, locale) also runs fully offline.

  used only for schema generation; no function tool or global warning filter is
  installed. Existing client interfaces, model, budgets and store=False remain.

  extraction incorrectly labelled it scheduled. A shared S04 evidence guard now
  withholds that contradiction before venue/route/explanation calls and retains
  the extracted status separately. It checks the same source URL and exact dated
  session, or a direct event-title cancellation beside its grounded schedule.
  Negation, conditional refund rules and other dates/times are not cancellation
  evidence. Exact known copies cannot erase a cancellation from another source.
- Source-scoped D03 IDs allowed the same known event/venue/address/start to occupy
  several alternatives and consume duplicate route requests. S04 now deduplicates
  only complete exact identities before the shortlist. Original source listings
