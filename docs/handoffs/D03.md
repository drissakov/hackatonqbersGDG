## Runtime response contract for S04/D04

Import `DiscoveryResult`, `NormalizedEvent`, `NormalizedSession` from the local
`models.py`. This is an internal handoff contract, not an approved shared HTTP schema.

| Field | Meaning |
| --- | --- |
| provider_status / provider_code | partial with grounded discovered events/listings; unknown for insufficient/malformed facts; unavailable for a missing required interface/provider failure |
| live_web_search | not_run for the pure normalizer/missing method; passed only after completed search/tool/source/citation evidence is observed; failed when attempted discovery fails |
| evidence | transient generated Responses text, consulted source URLs, citations; nullable when no acceptable search evidence exists |
| events | separately typed event metadata with venue, source URL, source_fetched_at, status listing/discovered, schedule_hints, missing_fields and sessions |
| sessions | session_id, event_id, city/venue, source URL/time, nullable starts_at/ends_at, price_from, currency, price_kind/conditions, status, verification and exclusions |
| rejected_events / excluded_sessions | rejected URL/city rows and rejected/ineligible sessions; not a city coverage metric |

`partial` here can contain listings, unlike the shared card envelope. Do not
coerce this DTO into EventSearchResponse or change the HTTP 503 scaffold until
Sabyrzhan approves a compatible transient/listing response. A bounded web search
cannot establish complete absence, so D03 does not produce `no_match` or `ok`.
Synthetic injected-client tests do not establish real network/model access even
when their simulated output has `live_web_search=passed`.

`source_fetched_at`/evidence `fetched_at` use the caller's aware observation-time
anchor. This is not a publication/index timestamp, an origin-server fetch-time
guarantee or proof that a session remains current. Source modification time is
unknown. The service stores none of this evidence in a corpus or index.

Citation `text` and indices preserve the API's exact cited slice, which may be
only a link marker. `context` separately retains at most 2000 characters of the
associated response paragraph/segment. That context is **generated Responses
text**, not a verified quotation from the original page. Date extraction must
match a cited response context and one adjacent explicit date/clock pair; these guards
prevent unsupported normalization, but do not independently verify the page.
Unsupported formats, nonzero seconds/microseconds, missing year/clock or
publication/index dates remain null. Local Astana date/year matching is performed
after timezone conversion, including UTC instants around local New Year.
Recognized listing URLs remain listings even if extraction calls them sessions.

Event titles keep source wording; translated/paraphrased or unsupported titles
are rejected. Unsupported city/name/address and blank optional values become
null. A different session URL must support that same event title and its own
metadata; parent-page city/venue facts are not automatically borrowed. These
checks prove support in cited generated response context, not source truth.

`verify_session(session, checks=[FieldCheck(...)])` accepts checks only from a
trusted caller after manual source review or a licensed feed. Each check names
the exact session_id, one field, exact value, matching session source URL, method and aware checked_at
at least as recent as the evidence anchor. Model extraction cannot submit checks.
`verification_status=verified` means **only the listed verified_fields** were
checked, even if that list contains just one field. All other fields remain
discovered/unknown; ticket_availability stays unknown. Existing checks are also
revalidated if the caller copied/changed the session. This method is not itself
a page fetcher or ticket-inventory verifier.

`recommendation_candidate` is only a preliminary input to S04 evaluation.
Known other cities, past starts, cancellations, unknown city/start/status,
wrong selected dates, starts before the request and conflicting source versions
are excluded. Cancelled duplicates dominate regardless of ordering. Event IDs
are scoped to source URL/title/normalized venue name/address; separate branches
and sources retain separate event identities. Known session IDs use the event
identity and UTC instant, independent of which session URL supplied the facts.
This is not a cross-provider global identity or a complete deduplication system.
When a venue is partial, a compatible cancellation from the same event source
blocks the scheduled version without merging the records. A cancellation with
unknown time blocks that compatible event pending review. Across separate sources,
an exact matching title, complete venue name/address and instant also withhold
the candidate. Explicitly different known branch addresses are not joined.

Unknown ends stay null/missing and cannot prove time fit. `price_from` remains a
lower bound with currency/kind/conditions. Amount and currency must be tied in
one source phrase; unsupported amounts, ranges, negated or contradictory prices
remain unknown. The phrase determines starting/promotion/regular kind, not the
extractor's label; unsupported conditions become null. Explicit free admission
can establish zero while currency stays unknown when absent. Budget, indoor,
travel/return feasibility, final eligibility and ranking belong to S04. D03
does not silently relax any request field and does not assert fit.

Venue matching uses NFC/case/whitespace normalization only, never name-only
merging, guessed aliases, language translation or nearest-place fallback. All
source records must be non-test OSM/municipal with storage **and** indexing
permission. Ambiguity returns null. The central Astana bounding box is only a
conservative geographic rejection gate, not an administrative-boundary proof;
coordinate_accuracy remains unknown because shared POIRecord lacks D02's center
accuracy sidecar. Peripheral or differently spelled addresses may not resolve.

   could lose context. Paragraph boundaries and exact-span reuse are now handled
   explicitly, with a safe failure for more than 100 unique action sources.
6. The amount of a discount could be mistaken for the ticket price, and unrelated
   free services could imply free admission. Discount-amount wording is rejected;
   explicit zero/free entry stays separate from free cancellation/delivery/drinks.
