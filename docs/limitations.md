# Release limitations

- Weather is omitted. No accounts, location history, ticket purchases or multi-stop routes.
- The hosted 2026-10-19 coverage check found 985 real OSM POIs and 985 embeddings, zero test POIs. This is not complete city coverage.
- Missing prices, hours, entrance accuracy and travel stay unknown. Visit duration is a labelled activity estimate, not a source fact.
- A request needs visit time plus five minutes for entry, five minutes buffer and all requested walking legs. Suggested walks adapt from 30 down to 10 minutes; source-checked playground visits adapt from 45 down to 10 minutes. Both reserve the total window and known travel without changing source duration facts. A 30-minute total window can fit a shorter visit; it does not promise 30 minutes at the destination. Other activity durations are unchanged; entertainment alone never proves a playground.
- Return travel is independent. Missing/unavailable legs cannot produce a confirmed total or time fit.
- A separate source-checked supplement contains 22 real Astana playgrounds, with explicit public access for eleven and unknown access for eleven. It supports generic child play only from `leisure=playground`; it does not establish age admission, safety, staff supervision, opening, free entry or physical condition. All names are derived labels because source names are absent; area points are approximate interior locations, not entrances. Source checks on 2026-10-20 are distinct from older source edits and unknown physical observation times. The supplement does not change or increase the measured coverage of the 985-record indexed corpus.
- No cafe has qualified branch-specific customer charging evidence. The charging filter and proof validation are covered with explicitly synthetic tests; actual charging requests remain unknown. Wi-Fi, grid electricity, chain-wide marketing, EV facilities and generic outlets do not establish USB, wireless, voltage or vehicle compatibility. The requested mixed family/cafe dataset therefore remains incomplete.
- Specific ages, quietness and accessibility remain unsupported facts. Recognized requirements, negative/optional conditions that cannot be safely resolved, and extracted explicit conditions return unknown. Child suitability, age restrictions and charging have structured local kk/ru/en warning explanations; source facts, dates and labels also re-render without a new search. Older responses retain their generic fallback. Phrase detection is bounded and extraction is still needed for other wording; named venues and morning exercise are not requirements by themselves.
- Direct playground requests and generic walks with a child use the source supplement even if extraction omits the child-interest code. A bounded kk/ru/en policy can add the entertainment destination category to a compatible walk request; explicit park, museum, cafe and other venue requirements remain restrictive. Only exact generic type descriptors can be removed from extracted name filters. Explicit names are retained, a lost explicit name fails closed, and derived display labels never prove a requested name. Recognized playground exclusions return unknown; inverse amenity search is not implemented. These guards are bounded phrase matching, not a general language parser.
- Feature retrieval examines all supplement records before route evaluation and respects the same 5 km geographic policy, requested name and other hard constraints. An empty supplement selection returns unknown because its coverage is limited. Missing price, hours, public access or route information keeps returned cards conditional. The runtime file is packaged read-only, with no automatic database import or reindex; ingestion audit validation is a separate required check.
- POI evaluation tries later candidates after proven time/opening/other conflicts until three non-rejected alternatives are collected, the retrieved pool is exhausted, twelve candidates are evaluated or the 54-second aggregate route budget expires. A conditional unknown card counts as a usable alternative, not a confirmed fit. The per-destination route timeout remains 18 seconds; outbound and requested return are separate. An unexamined tail yields unknown without cards or partial with retained cards and a warning. Exhausting the limited feature supplement still cannot establish city-wide no-match. Event-search selection is unchanged.
- Event discovery is a bounded live sample. Missing year/time/end, ticket inventory and unsupported prices stay unknown; discovered facts are not independently verified session guarantees.
- OpenAI intent failure returns unavailable, not no_match. Explanation failure uses a safe localized template; embedding failure can retain lexical candidates with a warning.
- Local provider access may fail without VPN. The hosted backend performs provider calls; browser/server credentials stay separate. Free Render can cold-start; provider/demo quotas remain external limits.
- 2GIS payloads and runtime event evidence are ephemeral and are not added to the persistent corpus or embeddings.
- Constraint clarifications carry structured request-field and reason codes for local kk/ru/en instructions. Conflicting requirements and numerical constraints that could not be parsed remain unknown until the user corrects and resubmits the request. While editing, only these codes remain visible as previous-search corrections; edits are not presented as checked until a new search responds. Older responses without this metadata keep a generic warning. No new weather or optional feature is included in this release.
